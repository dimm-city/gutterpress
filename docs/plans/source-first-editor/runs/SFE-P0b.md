# SFE-P0b — Hygiene and architecture fitness functions

## Objective

Prevent new architecture violations while the architecture changes: untrack generated
output, and install CI-enforced checks for generated files, dependency/import
boundaries (D4), the ProseMirror-family ban, and the desktop HTTP route ratchet —
each with a deliberate-failure (sabotage) self-test proving it can fail.

## Allowed behavior changes

- Remove the 7 tracked root `.svelte-kit/` files from git tracking (files are
  regenerated output; working behavior unchanged).
- Add `tools/check-generated-files.mjs` and `tools/check-architecture.mjs` with
  self-tests, root scripts, and CI steps.
- Tighten `knip.jsonc` only where removal does not depend on P5 deletions.

## Behavior that must remain unchanged

- All runtime behavior, builds, and public contracts.
- Knip exemptions tied to PWA scaffolding remain until P5a (each must be annotated
  with its deletion phase, not removed now).

## Binding decisions

- **D4** — package ownership map and import direction; no service locator in new code.
- **D10** — no new desktop HTTP route during P5 (the ratchet enforces route count
  never exceeding the recorded baseline).
- **Plan P0b** — every new architecture check requires a deliberate-failure proof
  (lessons G-12, AP-20: a gate must prove it ran and prove it can fail).

## Recorded facts (verified by the integrator)

- Tracked generated files at baseline: 7, all under root `.svelte-kit/`
  (`git ls-files | grep -E '(^|/)(build|out|dist|\.svelte-kit)/|\.tsbuildinfo$'`).
- Desktop HTTP route baseline: **104** `+server.ts` files under
  `packages/desktop/src/routes/api/`.
- Existing convention for tool self-tests: `tools/check-render-purity.mjs` +
  `tools/check-render-purity.test.mjs`, run by the CI `build` job.
- CI wiring and root `package.json` scripts are integrator-owned in this run
  (hot files; plan "Lane rules": shared hot files are assigned to one actor).

## Caller and consumer inventory

- CI `build` job consumes both new checks; root scripts consume the tools.
- `tools/architecture-baseline.json` is consumed only by `check-architecture.mjs`.

## Persistence and compatibility

- No runtime or public contract changes. Untracking `.svelte-kit/` does not affect
  builds (regenerated by `svelte-kit sync`).

## Security and trust

- Checks read the repository only; no network, no secrets.

## Determinism and resource limits

- Checks must be pure filesystem scans, deterministic, and complete in seconds.
- Exit codes: 0 pass, 1 violation, 2 usage/internal error (match check-render-purity).

## Test plan

- Each check ships a `.test.mjs` sabotage self-test (temp-dir fixtures, never the
  live repo state) proving pass AND fail paths, runnable standalone via `node`.
- Gate runs both self-tests, both checks against the live repo, and knip.

## Review dimensions

- Can each check actually fail (sabotage proven, not asserted)?
- Does the ratchet read the baseline from the committed JSON, not a hardcoded magic
  number inside the script?
- Do the D4 rules tolerate the not-yet-existing `packages/editor` and
  `packages/vscode-extension` without weakening once they exist?
- Did Lane C remove only exemptions provably dead today (nothing P5-tied)?
- Are the checks wired into CI such that a deliberate violation would fail the build?

- `node tools/check-architecture.test.mjs`

- `bun run check:architecture`
- `bun run knip`
