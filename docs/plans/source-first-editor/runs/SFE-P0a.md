# SFE-P0a — Execution baseline verification and record

## Objective

Record the exact post-`0.10.2` execution baseline and reproducible current behavior
(mutation callers, platform/transport surface) before any feature or deletion work,
so every later deletion can prove its inventoried callers moved or disappeared.

## Allowed behavior changes

- None. This run adds documentation and characterization tests only.

## Behavior that must remain unchanged

- All production code, configuration, dependencies, and public contracts.
- Existing tests: none may be modified, weakened, or deleted.

## Binding decisions

- **D1** — Baseline: `0.10.2` merged to `main`; work branch created from the recorded
  `origin/main` commit. Vocabulary: source/snapshot/source edit/projection/generated
  view/host/preview have exactly one meaning.
- **D15** — Every deletion claim requires search proof, dependency proof, and passing
  behavior tests. Every run records exact commands, exit codes, test counts, base SHA,
  head SHA.
- **Lane rules** — write only assigned paths; no ProseMirror-family dependencies; no
  new desktop HTTP routes.

## Recorded baseline facts (verified by the integrator before this run)

- Baseline `origin/main` SHA: `ea7b60d50340b75b9c58666e5063bcbbbb666576`
  (merge of PR #196, `release/0.10.2`).
- Work branch: `claude/sonnet-opus-agent-workflow-4s81ps` — **deviation**: the plan
  names `feature/source-first-rich-editor-architecture`; the execution harness
  designates this branch instead. Ancestry holds: the work branch was created at
  exactly the baseline SHA.
- **Deviation (release management, non-blocking):** the final `v0.10.2` tag has not
  been pushed (latest tag `v0.10.2-beta.2`; package versions read `0.10.2-beta.2`),
  and `origin/release/0.11.0` does not exist yet. The plan's equality precondition
  is vacuously safe — there is no release branch to diverge from and the work branch
  equals `origin/main` — so execution proceeds; release management must create
  `release/0.11.0` from this baseline and cut the final `0.10.2` tag.

## Caller and consumer inventory

## Persistence and compatibility

- No user data, no migrations, no public contract changes.

## Security and trust

- Documents may not contain secrets, tokens, or absolute user paths.

## Determinism and resource limits

- All counts generated by commands recorded verbatim in the docs, reproducible at the
  baseline SHA.

## Test plan

- Characterization tests only (bun:test, `packages/desktop/tests` conventions):
  pinned assertions that trip on unintended later change.
- New tests must pass at the baseline; liveness assertions required (no vacuous pins).

## Review dimensions

- Is every count generated from the recorded baseline with an exact command?
- Are feature callers distinguished from dead or test-only callers?
- Can later deletion prove every inventoried caller moved or disappeared?
- Do the new characterization tests pin behavior tightly enough that the P4/P5
  deletions would trip them if semantics silently changed beforehand?
